# Case-study materials

Start with [the recommendation and solution](CASE-STUDY.md). It explains the problem, proposed trust boundary, savings assumptions and decision gates.

The required written deliverable is [the one-page decisions PDF](Control%20Room%20-%20Key%20Decisions.pdf), also available as [editable text](KEY-DECISIONS.md).

Supporting material:

- [Who can change what](AUTHORING-CONTRACT.md): maker, engineering and production responsibilities.
- [Pilot scorecard](PILOT-SCORECARD.md): how to test reuse, ownership cost and the production controls.
- [Loom script](LOOM-SCRIPT.md): narration and exact demo sequence.
- [Independent review](INDEPENDENT-REVIEW.md): reproduced defects and repair verification.
- [Delivery record](DELIVERY.md): final source, timing, usage and remaining submission steps.

These materials do not claim that security guidance or passing tests make arbitrary generated applications safe. The proposal constrains the maker's authoring surface and keeps privileged logic in trusted code. Production identity, infrastructure and governance still require engineering ownership.
